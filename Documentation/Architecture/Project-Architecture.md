# Project Architecture

## Baseline

Unity 6000.5.5f1, C#, offline single-player. This is the exact editor already installed on the development Mac, chosen for immediate reproducibility. The installed editor is x86_64 and therefore uses Rosetta on the M3; before long-term work, migrate the project to a native Apple Silicon Unity 6 LTS editor after a tested version migration. `ProjectSettings/ProjectVersion.txt` is the pin. The Windows standalone module is installed; native Windows validation is not available in this environment. The project currently uses Unity's default render pipeline: the bundled URP 17.5.0 compilation failed inside package code with missing Unity rendering types even after a clean package resolve, so URP integration is deferred until a compatible editor/package combination is available.

## Modules

`Assets/_Project/Scripts/Core` contains serializable domain state for quests, inventory, and saves. `Player` owns movement and interaction input. `World` owns scene bootstrapping and the vertical-slice loop. The scene uses Unity primitives, a built-in camera, and IMGUI so no external art, UI package, input package, or paid service is required. Save files use JSON in `Application.persistentDataPath`.

The prototype keeps dependencies explicit and small. Runtime systems are composed by `VeyrathGameController`; data types remain independent of scene objects so they can be unit tested and migrated to ScriptableObject-authored content as the slice grows. Avoid adding a service locator or broad framework before a concrete need arises.

## Scene flow

`FirstLight.unity` contains the game controller. A runtime bootstrap applies persisted options and supplies a fallback controller if the scene lacks one. On play it builds the floor, capsule player, NPC, enemy, camera, and lighting. The player accepts the quest from Edda, defeats the Wraith, and returns for a reward. Quest and inventory state are serializable and round-trip through save/load. A settings facade persists display, V-Sync, frame limit, quality preset, and master volume; project logging prefixes messages by subsystem.

## World architecture

`RegionCatalog` defines the connected `first-light` and `ashen-reach` regions. `RegionStreamingManager` owns the active region, loaded-region set, additive scene-load hook, discovery list, travel anchors, world minutes, weather and LOD policy application. `AshenReach.unity` is a second build scene generated by the Editor setup. The world map overlay exposes the current region, connected region, time and weather state.

## NPC simulation

`NpcProfile` stores identity, faction, home region and routine segments. `NpcSimulationService` resolves deterministic activity from world minutes, advances offscreen NPCs when enabled, tracks relationships and serializes state. `NpcSimulationRuntime` registers Edda and keeps her activity synchronized with the region world clock; dialogue reflects activity and relationship context.

## Combat and boss architecture

`CombatArchitecture` keeps weapon definitions, damage calculation, status effects, enemy roles, adaptive tactics, boss phases, difficulty multipliers and balance telemetry as small testable core services. Weapon styles are data-driven (sword, bow, staff and hammer); repeated player patterns can trigger counter tactics, role rules protect allies or create distance, and boss phases switch by health thresholds.

## Story framework

`StoryRuntime` owns quest definitions and progress, objective advancement, prerequisite conditions, world consequence flags, dialogue choice effects and quest-bound companion recruitment. `QuestGenerator` produces deterministic authored-style side quests without coupling story data to the scene controller. Objective progress uses Unity-serializable lists so it can be persisted safely in a later save-schema integration pass.

## Faction, economy and conflict simulation

`FactionWorldSimulation` stores faction reputation/influence/treasury, territory ownership, regional stockpiles, risk-aware trade routes, conflicts, treaties and world reactions. `ApplyPlayerAction` provides a controlled hook for defend, trade and sabotage actions; daily simulation moves stock and funds along active routes while treaties suppress conflicts until expiry.

## Settlement and activity simulation

`SettlementState` stores residents, buildings, defense, morale, mounts and serializable resource storage. `SettlementActivityService` enforces the complete loops for gathering, fishing, hunting, cooking, alchemy and riding, plus building costs and daily food/morale upkeep. Requirements prevent free outputs and make each loop independently testable.

## World content catalog

`RegionCatalog` now exposes eight connected regions. `RegionContentDefinition` keeps authored content references grouped per region—settlements, ruins, dungeons, quests, NPCs, factions, bosses, items, resources, secrets and world events—so content can expand without changing streaming or simulation code.

## Audio and localization

`VeyrathAudioManager` owns separate effects/music sources, intensity state and safe clip fallbacks. `LocalizationService` serves Dutch and English text with key fallback and validation; `SubtitleService` handles timed dialogue lines. `TtsProductionManifest` tracks locale-specific voice assets and reports missing files without throwing or blocking the game.

## Endgame and balance

`CharacterProgression` clamps progression at level 4000 and clears overflow XP. `BuildProfile`, `GearCollection`, `EndgameService` and `BossChallengeState` provide bounded builds, set bonuses, repeatable activities, long-term reward currency and phase-based endgame bosses. `EndingResolver` converts world consequences into alternate endings.

## Next architecture steps

Separate input actions, combatants, dialogue/quest data, UI, and persistence as systems mature. Add assembly definitions after the runtime/test assembly split is established. Add additive zone streaming only after profiling a second connected zone. Preserve offline functionality and keep all content replaceable without hard dependencies on external assets.
